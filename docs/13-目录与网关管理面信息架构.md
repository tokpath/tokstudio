# 目录与网关管理面信息架构

对照：`docs/01` §4–6 / §9、`docs/04` D3–D5 / D13 / D16 / D24、`docs/05` 目录实体、`docs/06` 管理 API；竞品参考 LiteLLM / Portkey / OpenRouter / OneAPI。

## 1. 目标

平台管理员侧「提供商 / 模型 / 路由组 / API Key」页面字段冗余、职责糊。重新划清：

- 谁管用户 API Key；
- 「目录与网关」侧栏留什么；
- 路由挂在哪一层；
- 列表必看字段与操作入口放哪一页。

## 2. 已拍板结论

### 2.1 用户 API Key

| 角色 | 能力 |
|------|------|
| 终端用户 | 创建、查看完整 Key、轮换、改白名单/RPM/并发、禁用、过期 |
| 渠道管理员 | 本渠道用户 Key **列表（无密文）+ 禁用**；不能创建、不能改限额/白名单、不能看完整 Key |
| 平台管理员 | **不管**用户 Key：侧栏去掉；不再提供平台级查/禁用户 Key |

澄清：用户 API Key 是调 **TokenHub 网关** 的通行证，不是上游大模型 Key。上游钥匙在「提供商 → 账号池」。

### 2.2 侧栏「目录与网关」

保留三项：

1. **提供商**
2. **模型**（点进去两个 **Tab：目录 | 审核**，不是两个子菜单）
3. **路由组**

去掉：

- **API Key**（改到渠道台）
- 独立 **价格** 菜单（改价只在模型详情；`/admin/prices` 可删或仅过渡期兼容测试）

### 2.3 路由组

- **数据主键**仍是公开模型（`public_model_id`），对齐 OpenRouter「每模型一条 Provider 池」与现有 `docs/05`。
- **列表按 vendor 折叠**（`openai` / `anthropic` / `bytedance` / …），降低平铺冗余感。
- **厂商默认 = 模板**：可批量套到该 vendor 下尚未单独覆盖的模型；个别模型可覆盖。不是「只能挂在厂商、不能挂模型」。
- 澄清：Seedance 产品名 ≠ vendor；Seedance 的 vendor 是 **`bytedance`**。

列表必看：模型 ID、厂商、策略、候选 Provider 顺序（简写）、状态。  
详情再改：weight、`provider.only`/`ignore`、跨模型 fallback。  
不出现：成本价、上游 Key、能力 JSON、超时重试（归提供商）。

### 2.4 提供商

列表（接线本）：名称、类型（直连/聚合）、适配器、健康、状态、账号池数量。  
详情：Base URL、超时重试、凭据轮换、账号池、已挂模型等。  
列表不要：凭据指纹、已挂模型长串、成本。

**同步模型**：只在提供商详情「从该上游同步 → draft」；结果在模型「审核」Tab 消化。

### 2.5 模型

- 侧栏一个「模型」，内 Tab：**目录 | 审核**。
- **目录列表极简**：公开 ID、显示名、状态、途径 Provider；价格/能力/挂载进详情。
- **审核 Tab**：待审 / 待发布 / 已拒绝；创建人与审核人互斥规则不变。
- **挂载 / 弃用 / 改价**：只在模型详情。
- 手工创建可放审核 Tab 或详情入口，不回目录列表底部堆表单。

### 2.6 渠道台 API Key 页

列表：用户、Key 名称、prefix、状态、最近使用。  
操作：仅禁用（二次确认）。  
不提供：创建、改限额、改白名单、完整 Key。

## 3. 与旧文档的差异（摘要）

| 旧表述 | 新表述 |
|--------|--------|
| 平台可 `POST /admin/api-keys/{id}/disable`、侧栏有 API Key | 平台不管；渠道 `GET/POST` 本渠道 Key 列表与禁用 |
| 管理导航含 API Key、价格 | 目录与网关：提供商 / 模型 / 路由组；价格进模型详情 |
| 路由「每个公开模型独立配置」且无厂商模板 | 主键仍是公开模型；增加 vendor 折叠与模板套用 |
| 模型页单页堆审核+同步+挂载 | Tab 拆分；同步在提供商；挂载在模型详情 |

## 4. 竞品对照（决策依据）

- **LiteLLM**：逻辑 model group + default_fallbacks（默认+覆盖），不是 vendor 主键。
- **Portkey**：独立 Config 策略对象，可绑 Key/请求。
- **OpenRouter**：每公开模型 Provider 池 + 跨模型 fallback；最接近本决策的主键选择。
- **OneAPI**：渠道（上游账号）+ 分组；路由长在渠道/模型映射上。

本决策选 OpenRouter 式主键，用厂商模板降低运营重复，用独立路由组菜单（非塞进模型页）。

## 5. 实现边界（本 PR 不做）

- 不改前端菜单与页面。
- 不删 `/admin/api-keys`、`/admin/keys`、`/admin/prices` 代码。
- 不迁移 `route_group` 表结构（仍按 `public_model_id`；厂商模板可为应用层批量写多条 route_group）。

后续工程 PR 应：改侧栏与 Tab、挪表单、渠道 Key API、废弃平台 Key 管理 API，并更新 Playwright / e2e。
