# 渠道与分销规则

状态：**已确认，2026-10-10 同步最新业务决定**
替代已删除的 `docs/02-分销与代理商需求.md`，并覆盖 `docs/04` 中 D7、D8、D8.2、D9、D31 的旧分销口径。
最新用户决定及docs/18优先；本轮实现与实际验证见docs/21、26。

## 1. 渠道组织

| 类型 | 含义 | 可建下属 |
| --- | --- | --- |
| 平台 | 自营，等同平台 | 渠道、OEM |
| 渠道 | 推广渠道 | 无 |
| OEM | OEM 贴牌，业务上视为另一个平台（技术依赖本平台） | 仅 渠道，不可再建模 OEM |

- 平台与 OEM 各自经营一个品牌。OEM 与平台是技术合作关系；平台管理直属渠道和 OEM，OEM 管理自己的直属渠道。渠道继承所属品牌，使用推广工作区查看有权客户、模型和本人收益；普通邀请用户始终留在同一用户账户。
- 同一品牌只使用一套终端套餐和售价：平台 制定 平台 品牌套餐，OEM 制定 OEM 品牌套餐；渠道 不创建、发布或下架套餐。套餐可适用于整个品牌或指定直属 渠道。平台与 OEM 各自发布和下架自己品牌的套餐。
- 渠道 只管理本渠道用户、推广及已授权模型的本地上下架，无收款、购买、划拨或商户配置权限；上级平台可管理直属 渠道 的状态、管理员与模型授权。OEM 的下属 渠道 不出现在 平台 的日常管理列表，平台 不代 OEM 创建、停用或交接该 渠道。
- 全库只有一个 平台。可以有多个 OEM；OEM 不能再建模 OEM（避免把品牌再转卖到第三国）。
- 每个 OEM 使用独立品牌；开通时可选择尚未分配的真实品牌或同操作创建品牌配置，不要求手输品牌ID。渠道创建时自动继承上级品牌；组织类型和品牌归属创建后不在详情更改。
- 平台协助 OEM 配置到可营业后交接；OEM 负责本品牌的日常经营，技术服务与服务额度由平台提供。
- 只有 平台/OEM 是收款与资金管理主体。渠道 用户直接向所属品牌 平台/OEM 付款，渠道 不经手充值购买，不持有独立积分池。
- OEM 及其下属 渠道 共用 **OEM 的**分佣比例与达线（OEM 相当于该市场的「平台」）；支付商户属于 平台/OEM，渠道 共用所属品牌的商户与收银台规则。
- OEM 不维护上游 Provider、密钥、模型目录、网关基建。

## 2. 推广

链：渠道 → 代理商 → 个人推广员（推广员可再发展推广员）。
计佣只沿邀请链向上 **两跳**（直接、间接），避免多层法规风险。

- 代理商是独立角色，渠道后台可建，再发展个人推广员。
- 个人推广员：渠道台种子；终端用户达线后获得分佣资格。
- 注册即为每个用户生成专属推广码，并记录 **分佣资格**（默认无）。
- 无分佣资格时，分享只发赠送积分，不发佣金。
- 注册未带他人推广码：不发佣金。
- 无间接推广者：只发直接（例如渠道直属推广员）。

## 3. 分佣

三个可配比例：总佣金、直接、间接。直接+间接不得超过总。
平台、渠道 共用平台一套；OEM 自改（作用于 OEM 及其下属 渠道）。
基数：已确认 API 消耗（批发价），充值不计佣。
所得进入用户 **现金钱包（佣金钱包）**，不用于抵扣 API。
冻结期后解冻；P0 仍可人工结算打款。

## 4. 积分与钱包

金额:积分 = 1:1。OEM 先向技术平台取得服务额度；用户充值或线下付款后的划拨由品牌 平台/OEM 执行，OEM 及下属 渠道 客户从 OEM 池发放，平台直属 渠道 不消耗 渠道 池。不必另立「库存」领域名。

用户消费顺序：**赠送积分 → 充值积分**。赠送积分不可退款。
达线规则（累计消费 / 单笔充值、满多少）与赠送触发条件均可配置；平台/渠道 在平台，OEM 自己配。

## 5. 品牌经营账户

流水为准，汇总可缓存。

- **充值汇总**（正）
- **剩余额度 / 实际消费**：未发放与已发放未消费分别保留；实际消费是原品牌完整范围内已确认 API 消费减原冲正，不把已发放客户余额当作利润。
- **营销子账户**：不是预算，而是已产生支出，用 **负数**。内部分 **冻结**（佣金未解冻）与 **已发放**（已解冻佣金 + 即时积分奖励）。解冻只转档，总额不变。
- **供应商支出**（负）：线下已付款、线上只记账。平台 记付给模型商；OEM 记付给技术平台；渠道 不录入资金支出。录入不填渠道，系统按操作者账本写入。

**OEM API毛利** = 本品牌终端实际净消费 − 同批消费的原平台服务结算成本。例如用户计费150、实际消耗100，毛利50。佣金/营销支出另外列示；预付平台1000采购服务额度的现金支出不再混入这50的毛利，否则会重复或提前确认成本。

**平台与OEM交易**：OEM付款并收到对应服务额度时，该笔采购交易完成。平台记录自己的服务额度销售/收款，不等待OEM终端消耗，也不关心其终端售价来核算自身经营。平台自营终端消费、对OEM销售、实际服务成本与现金收支分开。OEM终端明细仅按技术协助排障权限保留。渠道仅有推广归属和本人佣金。

**已执行请求超出预估**：按可靠实际用量全额结算，允许账户负余额及Key实际用量超限；充值自然补齐。余额/限额不足时禁止新请求，用户弃用形成的小额缺口由所属品牌平台/OEM各自承担，不新增催收。

## 6. 冲正

不得删原流水。所有相关账户成对补记并可溯源：用户充值积分 / 赠送积分 / 佣金钱包；平台/OEM品牌服务额度、实际消费/未消费、营销冻结与已发放；供应商支出。冻结中的在冻结档回冲，已发放的在已发放档回冲。每条含原分录 ID、原因、操作人、时间；同一幂等键只成功一次。

## 7. 本仓库落地状态

以下为 2026-09-09 的历史落地记录，实际当前实现与本轮证据分别见 docs/21、docs/26；不作为本轮全部已验证声明。

已落地：渠道父子约束（平台 建 渠道/OEM，渠道 无下属，OEM 只建 渠道）；OEM 管理员只能在本组织下建 渠道；OEM 下 渠道 客户共用 OEM 的服务额度池，不向 渠道 池划拨；分佣/达线仍按 OEM 覆盖其下属 渠道。注册预发推广码；用户 `can_commission`；计佣两跳 `direct`/`indirect`；无资格或无推广角色不计佣；佣金计提写入渠道营销冻结流水，解冻转到已发放并入账用户佣金钱包（不抵 API）；用户钱包区分赠送积分与充值积分，消费顺序为赠送 → 充值，赠送不可退；达线规则（累计消费 / 单笔充值）可配，平台/渠道 走平台、OEM 可覆盖，达标自动赋 `can_commission`；供应商/向上游付款线下支出只记账（金额为负；必填金额、来源类型、幂等键；`channel_org_id` 由系统按操作者账本写入；冲正成对补记）；渠道盈亏汇总 API；OEM 工作台可改本池分佣比例；无分佣资格的分享在被推荐人注册时发赠送积分并记营销已发放。渠道台 `/channel/ledger`、`/channel/rules` 与管理台账本/达线页面对应这些接口。

未完成：P0 佣金打款仍为人工。

旧行为废止：渠道独立采购价/资金池/终端价，无推广角色记渠道 10%、固定 KOL 三级当目标树、四桶 team/channel/override、营销正数预算账户。

## 8. 人工佣金打款与退款核对（2026-09-18）

- 线上登记仅记录已经完成的线下打款，不调用银行或支付商转账。新登记在同一事务中保存对象、金额、实际时间和可选外部参考号、扣减原收款人佣金钱包、记录 `commission_payout` 出账和更新结算状态；原佣金未入账或余额不符时拒绝登记。同一结算单或原操作重试只执行一次。
- 未打款佣金退款时冲回原佣金钱包；已经打款的佣金退款时不再扣钱包，也不扣 API 积分或自动抵扣后来获得的佣金。账务模块另记 `billing_commission_recoveries` 待核对金额，关联原佣金、入账流水、出账流水和结算单。用户钱包与结算单显示待财务核对提示。
- 待核对记录不表示资金已经追回。财务或平台管理员可在佣金页面登记线下已经实际收回的款项，支持部分收回。每笔保存金额、实际发生时间、可选说明/外部参考号及系统操作人和记录时间；收款记录、累计已收回金额、审计及审计事件在同一事务提交。相同操作重试不会重复登记，可靠外部交易号重复、超额登记和结清后新增登记均拒绝。全部收回后标记结清，历史凭证保留。本版本不提供自动转账、自动追回、自动抵扣或豁免。历史人工打款单不自动补扣钱包，上线前须单独核对历史余额与付款证据。
- 财务/平台管理员可读写追回记录，审计只读；其他后台角色无权访问全量记录。用户在同账户“邀请与收益”查看自己的金额、结清状态及收回记录，不展示内部备注或财务操作人。钱包待收回金额仅汇总未收回部分，结算单和同账户邀请与收益同步显示部分收回/已结清状态。
- 封禁/解封的用户状态与相关佣金状态在同一事务提交；佣金入账失败时用户状态一并回滚。收款角色查询共用账务事务连接，读取失败不会静默跳过入账。


## 9. 历史佣金核对与计算快照（2026-09-21）

- 新计提保存原分佣策略快照及原收款角色，和消费账务共用事务；读取归因、资格或策略失败时整体失败，不静默少计。策略调整创建新版本，不覆盖历史策略；冻结天数允许明确设为 0。
- 重算接受消费请求编号或用量编号，使用消费原批发价和佣金原快照。已经正确的记录保持不变，不重新开始冻结、不重复扣款。没有有效佣金时不根据今天的资格补发，已退款消费不恢复佣金。
- 仅仍处于冻结状态且有完整原快照的计算差额允许自动成对冲正重建；保留原到期时间，原记录与新记录可追溯。修正、营销记账及审计事件同事务；失败整体回滚。
- 历史缺快照，或已经解冻、暂停、结算、打款的差额，必须人工核对资金凭证，不从当前配置猜测历史应付金额。本次迁移不伪造旧快照或自动补扣历史余额。

### 管理员交接

新建 OEM 下的 渠道 继承 OEM 品牌，模型授权初始为空。平台只给官方直属 渠道/OEM 授权；OEM 只能从自己已授权且已上架的模型中授权给直属 渠道，并可撤销。渠道可自行下架本渠道模型，渠道没有下属；自行上架不能越过上级撤权。平台模型全局下架立即使所有渠道不可用。已有渠道不自动改品牌或授权，须先核对实际经营归属。

平台管理员在渠道详情的“渠道管理员交接”中操作：接手人先通过该渠道推广链接注册，再从已注册同范围客户中检索并选择授权；原因或备注可选，必须复核实际目标账号与授予权限。目标须为该 渠道/OEM的正常用户，不能叠加其他后台管理角色。授权不更改注册归属，不创建或代管密码，不授予平台权限。可在同一入口撤销，个人账户和历史账务保留；权限与审计同事务，重复请求不会重复授权。上线交付前必须核验接手人实际登录后能看到正确渠道，撤销后现有会话不再有管理访问。


## 10. 角色任务导航（2026-10-10）

平台、OEM 和渠道分别定义任务导航。平台围绕工作台、客户与合作方、模型与套餐、资金与结算、异常处理、经营分析、设置；OEM 围绕工作台、客户与推广、模型与套餐、资金与结算、业务异常、经营分析、品牌与团队。渠道仅有工作台、客户、推广、已授权模型、我的佣金。菜单、快捷操作与深链使用同一权限矩阵。

普通用户始终使用同一 API 账户；邀请链接、人数、赠送积分、达线进度与个人佣金集中在“邀请与收益”，不需要独立推广者开户。专业推广客户能力按原服务端范围呈现。

业务、技术与财务字段仍按岗位裁剪；OEM 无上游报价/密钥/路由配置，渠道无资金池/收款/采购。

## 11. 品牌收款（2026-10-09）

支付与资金权限按 docs/12 执行。用户在线付款直接进入品牌 平台/OEM 商户；线下付款后由品牌财务在线划拨长期有效额度。渠道 只负责推广和用户管理。支付单分别记录推广归属和实际收款主体，发放保存来源池；退款回原池。佣金提现继续线下打款、线上记录凭证、操作人和时间。

## 12. 线下留痕与技术兼容

对象、金额、币种、实际发生时间和已实际发生确认是必要事实。票据、附件、外部参考号和说明可选，幂等依赖系统操作身份和业务单据，不依赖备注。相同备注可对应不同交易；内部记录号不能冒充外部付款凭证。

历史类型代码仅用于技术映射：`A → platform`、`C → oem`、`B → channel`。本轮不直接替换数据库枚举，业务界面只显示平台、OEM、渠道。
