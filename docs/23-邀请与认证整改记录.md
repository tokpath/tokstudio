执行范围：T10、G01/G04/G14/G20/G24/G25，以及同一普通 API 账户中的邀请与收益。实施分支 `codex/referral-experience`；基线 `6c2e164`，继承导航基础 `2ceed00`。

## 已实施

- 邀请概览、专属邀请码/链接、已邀请人数、本人获赠与剩余积分、本人累计 API 消费和最高单笔充值达线进度，集中在 `/app/referral`。
- 同一账户展示个人佣金完整历史汇总和分页明细、结算打款与追回事实；佣金不与 API 赠送积分合并。
- `/partner` 及其三个旧子入口兼容重定向。专业推广客户视图继续按原权限隔离；普通自动邀请身份不获得专业客户权限；旧收益接口限定本人角色的收益。
- 汇总覆盖完整历史，不使用最近一页作为累计额；空 membership 返回空数据，避免 legacy list 空范围代表全量造成泄露。
- 专业账户有多个推广码时，每个码由服务端生成所属品牌的 canonical 分享链接。邀请资源按本人、品牌、分页隔离，身份切换不接收旧响应。
- 登录/注册/OAuth 保留合法站内 `next` 和 `promotion_code`；OEM 无码注册归当前品牌，跨品牌邀请码拒绝。统一公开注册链接为品牌真实 origin 的 `/login?promotion_code=...&next=...`，带码默认注册。
- OAuth 状态在服务端保存品牌与原任务，失败后恢复邀请及任务。短期 host-only、HttpOnly、SameSite=Lax 浏览器挑战绑定所有回调和重放；Google 入口只对配置回调可建立同 host 会话的品牌公开。
- 真实 Google exchanger 拒绝未验证邮箱；Google subject 优先匹配，已绑定其他 subject 的同邮箱拒绝。新 OAuth 账户使用不可预测的随机密码；注册、绑定及发会话在事务中完成，更新错误不再忽略；未修改已有密码。
- 首页、价格、邀请页和 OEM 介绍使用真实品牌目录/已发布套餐。读取失败与空数据分别展示，移除虚构模型、排行榜、固定价格和未实现工具宣传。公开目录和说明无需登录；创建 Key、邀请与购买才进入登录回程。旧 quickstart/vibe-coding 归并真实模型说明并保留 model/next，公共 docs/integrations 由 T09 接管。
- 套餐购买保留选中 plan 与原任务，显示实际价格、币种、周期、权益和期限。可用支付方式来自真实收银台；无可用方式时不可下单。
- 新购买使用独立操作 ID；服务端持久绑定用户、品牌/渠道与原参数，订阅和订单原子提交，第三方 Checkout 在提交后调用，Stripe Checkout 沿用原订单幂等键。并发/刷新/超时继续原操作，确认完成后同套餐可发起新的购买。
- 当前收银台没有可核实的未来扣款授权链路，因此新购买只支持手动续费；界面不提供自动续费勾选，服务端拒绝任意 payment_method_ref/auto_renew。历史已授权订阅和已落库原操作快照保留。
- 旧 `/partner` 四个入口在 middleware 先归并收益页，避免根布局旧专业身份鉴权截住跳转；不放宽实际 API 权限。
- 钱包充值也使用独立持久操作：原用户/品牌/渠道/支付方式/金额绑定，充值与订单原子提交后才调用 Checkout。并发仅创建一单；超时、500、临时 404 和已知订单回读失败均保留原参数/原操作/原订单，确认终态后可重新充值。
- 旧公开分享 `/?promo=...` 和任意公共页面的有效邀请意图按同 host、品牌保存 30 分钟；公共导航及首页目录/文档链接带码，浏览后进入登录自动恢复码，不增加注册步骤，实际注册仍由服务端校验品牌和码。
- 登录表单明确原生 `method=post`，客户端接管前输入字段与提交禁用，防止慢加载或无 JavaScript 时浏览器以 GET 把邮箱/密码写入 URL，也避免接管前输入随后被重置。

## 钱包与邀请体验收口

钱包统一为充值、套餐与额度、订单与流水三个标签。旧 `/app/plans` 保留已选套餐及合法原任务，转入钱包套餐标签；返回目标会排除钱包/套餐自身以防循环。套餐与充值草稿仍按用户和品牌隔离，未知查询（含成功响应但缺少订单事实）保持原操作。临时支付方式读取失败只影响支付能力，不隐藏已读套餐。佣金指标和收回历史移到邀请收益，钱包保留必要入口。

兑换、已确认支付后发送本人+当前品牌范围事件，同步顶部余额、个人流水和额度。慢的旧余额响应不能覆盖新结果。兑换成功提示不被余额回读覆盖；二次读取失败另显示分区提示，保留已经确认的动作。未达分佣资格且无历史收益的账户只显示邀请码、赠送积分和资格进度；有历史财务事实仍保留佣金/结算入口。

新增 `/v1/me/wallet-records` 服务器按会话本人读取个人订单、流水及佣金收回记录；每页25条，全量总数，按时间+ID稳定游标并绑定本人及记录类型。原始历史资金事实不删改；收回回执保留，内部操作者/备注不投给普通客户。读取失败或失效游标不会伪装成0条记录。邀请测试付款参考号改为每笔唯一，保留隔离和实际回执断言以及交易号防重。
