# 订阅连接配置

每个供应商类型使用一项部署配置。先向供应商登记用于平台推理的 OAuth 客户端和回调地址。回调使用 `TOKENHUB_WEB_ORIGIN`，形如 `https://platform.example/api/v1/subscription-oauth/gemini/callback`。经营人员随后可在「平台技术 → 订阅账号池」用同一个浏览器逐个授权账号。

在服务端环境变量 `TOKENHUB_SUBSCRIPTION_CONNECTIONS` 中设置 JSON 对象，键取 `codex`、`claude`、`grok`、`gemini` 或 `antigravity`。每项使用该供应商发给平台的参数。

| 字段 | 值 |
| --- | --- |
| `authorization_url`、`token_url` | 授权码和 PKCE S256 对应的 HTTPS 端点。授权 URL 可携带供应商约定的选账号或离线授权参数。 |
| `client_id`、`client_secret`、`token_auth_method` | 已登记的客户端 ID，按供应商要求设置密钥。认证方式可选 `client_secret_basic` 或 `client_secret_post`，省略时使用请求体。 |
| `scope`、`resource` | 空格分隔的授权范围和可选资源标识。推理权限以及刷新权限以供应商合同与授权为准。 |
| `issuer` 或 `userinfo_url` | OpenID Connect 签发者与 `openid` 范围，或返回稳定 `sub` 的用户信息端点。 |
| `inference_url` | 接受所授 Bearer Token 的完整推理地址，与上表 OAuth 客户端获准的用途一致。 |
| `media_preset` | 可选。为供应商批准的连接选择一个标准媒体协议，服务端由推理地址生成各能力的端点。纯文本授权留空。 |
| `media` | 可选。供应商为平台提供定制地址时，可按能力覆盖标准地址。 |

Codex 和 Grok 使用以 `/responses` 结尾的 Responses 地址，Claude Code 使用 `/messages`，Gemini 和 Antigravity 使用 `/chat/completions` 兼容地址。Grok 和 Antigravity 需要获准用于平台推理的供应商连接。Gemini 可连接获准使用、调用纳入订阅费用的 Google Cloud 项目。账号池的实际费用以供应商原币账单为准。[Gemini 兼容接口](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/migrate/openai/overview) · [Google Antigravity 服务条款](https://www.antigravity.google/terms)

凭据导入可使用获准的导出 JSON。填写 `account_id`、`access_token`、RFC 3339 格式的 `expires_at`，有刷新凭据时填写 `refresh_token`。Codex 与 Claude Code 继续接受面板说明的授权格式。所有客户端密钥与账号凭据均由服务端处理。

## 添加账号和发布模型

经营人员在账号池展开「账号管理」，点击「添加账号 → 在浏览器授权」。每次授权添加一个账号。成功后账号立即可供池内已启用的路由调度，名称自动生成，可在账号管理中修改。

浏览器授权成功后，后台从已批准连接读取模型目录。多账号调度优先选目录中已列出所请求模型的账号。后台对可识别的模型准备「供应商模型」草稿。公开模型已有相同 ID 和模型标识，且还没有路由时，同时准备一条停用的路由。经营人员可在现有页面审核价格和发布。上游未提供目录时，账号仍能加入已有路由，也可从池卡片进入「添加供应商模型」。

## 媒体能力

| `media_preset` | 适用账号池 | 自动得到的能力 |
| --- | --- | --- |
| `codex` | 获准调用 Codex 原生 Images 的连接 | 图片生成、图片编辑，从 Codex Responses 地址推导同源原生端点 |
| `xai` | Grok | 原生图片生成和编辑、视频生成和任务查询。`grok-imagine-video` 可编辑和续写视频 |
| `gemini` | Gemini、Antigravity | 从 Gemini 或 Vertex AI 的 OpenAI 兼容地址推导原生图片端点 |
| `openai` | Codex、Grok、Gemini、Antigravity | OpenAI 兼容图片生成及编辑，含 SSE 预览 |

标准预设由部署人员随供应商连接配置一次，添加账号时无需填写媒体地址。公开的 Sign in with ChatGPT 订阅授权预览仅提供其文档列出的能力，其中生图需要独立获准的连接。更换已用账号的部署连接或启用媒体时，请重新授权该账号。[Sign in with ChatGPT 预览限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) · [sub2api Codex 图片支持](https://github.com/Wei-Shaw/sub2api/blob/v0.2.25/README_CN.md#openai-图片模型)

需要用 `media` 配置定制地址时，OpenAI 兼容图片地址以 `/images/generations` 或 `/images/edits` 结尾，可按上游能力设置 `"streaming": true`。Gemini 原生图片地址以 `/{model}:generateContent` 结尾。xAI 原生图片连接填写相应的生成和编辑地址。原生 Gemini 和 xAI 图片连接使用同步结果，平台也可将它们作为异步图片任务受理。

定制 Grok 视频连接同时配置 `video_generation` 和 `video_retrieve`。xAI 原生地址分别以 `/videos/generations` 和 `/videos/{task_id}` 结尾，平台可从上游返回的结果地址取得视频。OpenAI 兼容地址分别以 `/videos` 和 `/videos/{task_id}` 结尾，同时配置 `video_download`，以 `/videos/{task_id}/content` 结尾。按部署的上游地址规则登记供应商提供的 HTTPS 域名。

客户可以用 `POST /v1/images/generations/async` 或 `POST /v1/images/edits/async` 提交一项图片任务，用原 API Key 和 `GET /v1/images/tasks/{id}` 查询。收到任务号或首个流式预览后即记录交付。后台根据最终可核实用量结算，继续提供保留期内的结果。

`POST /v1/images/batches` 一次可提交最多 20 项，使用同一公开模型。每项填写 `custom_id` 和 `prompt`，可用 `output_count` 指定张数，用 `reference_images` 提交编辑素材。提交时按整批锁价和预占，结果按原请求逐项结算。使用原 API Key 查询、取消未完成项或下载单项图片和 ZIP。

Grok 视频编辑使用 `POST /v1/videos/edits`，续写使用 `POST /v1/videos/extensions`。两种请求都可提供 HTTPS 或内联 MP4 的 `video.url`，使用原视频任务接口查询和下载。续写的 `duration` 表示新增片段秒数，账单按核实的最终成片时长和配置的规格结算。标准 `xai` 预设会生成两条地址。使用定制地址时，`video_edit` 和 `video_extension` 分别以 `/videos/edits` 和 `/videos/extensions` 结尾。

## 文本调用

已发布的 Codex、Grok Responses 模型可通过 `/v1/responses`、`/v1/chat/completions` 或 `/v1/messages` 调用。已有 Chat Completions 能力的公开模型继续走原有 Chat 路由。兼容请求使用同一条 Responses 路由和原有的 ATG 结算，按已核实的上游 token 用量计费。`/v1/messages` 接受 `X-Api-Key`，保留 Messages 流事件格式。

Codex 上游使用无状态 Responses，无法执行低于模型已核实上限的输出限制。Chat 请求可省略输出限制，Messages 请求的 `max_tokens` 需覆盖模型的已核实上限。具体可用字段以已授权的模型连接为准。

`GET /v1/responses` 可升级为 WebSocket。每条 `response.create` 发起独立推理并按核实的 token 用量结算。同一连接按收到的顺序处理各轮，可用 `previous_response_id` 继续近期响应。客户端用相同的 `event_id` 或 `idempotency_key` 和请求内容重连，可取得保留期内的原结算结果。新一轮要继续已断开连接的对话时，提交完整上下文。
