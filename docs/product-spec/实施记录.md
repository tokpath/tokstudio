## 多角色仿真验收（2026-10-18）

**实际使用方式。** 主代理统筹三名 GPT-6.1 Sol 极高推理档代理，分别模拟客户与 KOL、OEM 与渠道、平台技术及品牌运营，主代理负责财务与独立复核、跨域资金修复及最终集成。使用生产构建、真实浏览器、隔离 PostgreSQL、Redis、私有 S3、后台任务，以及项目外独立模型和支付协议服务。新增九条跨角色完整旅程，不通过拦截应用 API 或直接填入最终账务结果来制造通过。

**客户与资金闭环。** 实际完成邮件注册与归属确认、同品牌跨渠道重复注册拒绝、KOL 活动与明确开放的促销组合、80 USD 购买 130 ATG、多个 Key 共享额度及各自预算、实际调用和幂等重放、两跳佣金确认、提现取消释放、停用恢复及注销中的推广关系保护。普通邀请人未获得 KOL 权限或佣金。财务与另一名复核人员实际办理两笔部分收款合并为 100 USD、20 USD 未使用余额退款、结果未知保留占用、核实后完成清偿；客户权益不承担商户手续费。票据实际上传私有对象存储、按来源检索和授权下载，并拒绝其他客户读取。

**经营与平台闭环。** OEM 从界面建立渠道并邀请负责人，完成授权、独立定价、采购交付、补货授权修订、采购余额退出退款、超卖风险预警及渠道接管。接管后客户权益与原 Key 继续可用，品牌按自身价格履约；负向结清差额按正确付款方向完成。线下自动补货只产生一张未付款订单，不虚增采购余额。平台技术人员实际轮换凭据、修订模型和路由，经营人员按正常提前通知排期上架与调价，生效后客户经 Bifrost 调用独立模型服务，账务确认 0.017 ATG，重放不重复扣费。另完成 OEM／渠道配色与 Logo、未验证域名保持停用、人员邮件邀请及细权限、风险规则版本冲突、通知、三类私有报表导出和越权拒绝。

**发现并修复。** 独立登记的线下采购收款原先不能完成退出退款，现按真实原收款证据和全局付款事实去重处理，保留记账失败后的核实事实并阻止重复执行；接管负向差额现按绝对金额核对进度、单独展示方向。首次模型上架不再绕过明确生效排期，通知规则可读取实际版本；刚交付额度展示与交付统一使用数据库业务时钟。修复财务报表截止分钟遗漏刚确认费用、发票搜索未生效、请求／采购导出被错误拒绝及导出行数不显示。补齐 KOL 活动业务表单、具名人员权限、退款记录中文分类与本页搜索。对照产品说明书还补齐 A112：限制复核超期提醒、持续提醒和升级，并验证解除、改期、撤权、接管和旧邮件积压不会继续错误通知。

**最终结果。** 全新数据上的完整浏览器验收 **122 项通过、0 失败、0 跳过、0 不稳定重试**，包含此前 113 项覆盖与新增九条角色旅程。最后一项退款类型显示修正后，重新生产构建，受影响的 102 项页面／经营交互／财务检查和一条普通购包调用链再次通过。最终前端 **107 项测试（14 个文件）**、TypeScript、生产构建、11 项 OpenAPI 契约及生成物检查通过；受影响的 ledger、organization、cooperation、payments、operations、portal 六个包整包 `-race -p 1` 通过。A112 另有四项真实 PostgreSQL／独立 worker 回归；替换进程重跑没有重复提交邮件。

**证据与复现。** 日志、最终截图、失败记录及脱敏摘要位于本机 `local/simulation-20261018/`，摘要为 `final-acceptance.json`。保留原始失败，不将其覆盖为成功：首轮整组遇到财务异步交付等待过短，以及旧脚本默认选中客户列表第一人；核实真实状态并修正脚本后，以全新数据完整重跑。显式设置 `TOKENHUB_SIMULATION=1` 与 `TOKENHUB_FRONTEND_ACCEPTANCE_FILE` 启动 `TestExternalFrontendAcceptanceServer`，生产前端连接该隔离服务后执行 `web/e2e/`。完整重跑应重新建立夹具，避免复用已接管或注销的账号状态；删除就绪文件会停止夹具并清理其独立数据库 Schema。邮件、付款和供应商凭据均为合成环境，真实商户认证、资金结算与公网域名启用仍须材料齐备后配置并实测。浏览器流程与领域证据共同验收，不宣称穷举所有角色和状态排列。

## 前端重构与验收（2026-10-18）

**功能组织。** 客户端按概览、模型接入、API Key、用量账单、套餐资金、邀请收益及账户服务组织；经营端按工作台、客户、资金办理、营销销售、采购合作、报表、设置及平台技术管理组织。已确认功能均保留办理入口，权限、经营主体类型及业务开通状态决定实际可用操作。平台维护模型、供应商和路由，OEM 与渠道经营权限仍遵循原业务边界。

**完整流程。** 客户可从模型价格与接入示例进入购包、付款、到账、额度来源、续费和调用账单。经营人员可在客户工作台内关联订单、资产、调用、推广、提现、票据及异常处理；订单工作台串联核实收款、资金分配、交付和退款。品牌外观、模型授权、价格、风险规则、采购授权及财务政策使用实际对象和版本编辑。平台与上级的配置权限不自动开放下级客户明细。

**关键交互。** 金融提交结果不明时保留原请求和幂等键，锁定编辑与离开操作，重试回读同一业务结果；创建 Key 的密钥仅展示一次。收款方式分别展示银行账户、线上支付和链上付款信息。采购授权修订保留原编号，要求明确重新确认，更换商户或部分更换付款资料不能沿用不匹配的旧资料。活动关联套餐不会覆盖活动自身加赠额度或版本。退款、提现及风险政策均读取自己的真实版本，避免误用列表首条业务记录。

**最终验证。** 生产构建、TypeScript、13 个文件中的 **102 项前端测试**、**11 项 OpenAPI 契约测试**及生成物漂移检查通过；当前契约为 204 条路径、183 份 Schema。全量后端 `go test -race -p 1 ./...` 通过，最后修改的 payments、cooperation、operations、portal 随后整包复跑通过；最终客户上下文权限补充另有真实 PostgreSQL 专项通过。

**浏览器验收。** 完整 Playwright 共 **113 项通过、0 项跳过**，包括 98 项真实接口页面检查（51 个经营页面、17 个客户页面、9 个公开页面，以及 21 项移动端检查）、14 项交互与权限场景，以及 1 条不拦截 API 的真实交易链。桌面与 390px 移动端未出现根页面横向溢出、浏览器异常或后端 500；关键页面截图已检查。交易链实际完成：100 USD 套餐下单、线下收款证明登记、原单分配及交付、获得 120 ATG、创建 Key、通过 Bifrost 请求独立模型协议服务、扣除 0.017 ATG、原请求重试不重复扣费，并在客户账单和经营客户工作台追溯同一次调用。

**证据与边界。** 测试使用隔离 PostgreSQL、Redis、私有 S3、独立模型与支付协议服务；没有真实客户、真实收款或资金转移。最终日志、截图及摘要在本机 `local/frontend-20261017/`（目录沿用启动日期，最终执行日期为 2026-10-18）。复现入口为 `web/e2e/live-business.spec.ts`、`web/e2e/live-coverage.spec.ts` 和后端显式启用的 `TestExternalFrontendAcceptanceServer`。真实商户及供应商材料仍按用户决定在齐备后配置并核验；协议联调不代替真实商户认证。页面覆盖与领域、HTTP 测试共同形成验收，不将其表述为全部业务案例的所有角色、状态组合均已逐一进行浏览器操作。

## 交付内容

**经营体系。** 平台、OEM 和渠道分别经营，品牌、客户服务归属、供货关系与推广关系分开建模。注册邀请、两跳推广、员工权限、独立复核、开业检查、分项经营状态、风险冻结和退出均有流程。平台可配置 OEM 域名、配色及 Logo；直属上级可配置渠道配色及 Logo，逐字段继承品牌默认外观。合作关系不自动开放下级客户财务。

**资产和销售。** 新账本使用 NUMERIC(38,18)，记录来源、占用、分录、余数与追加冲正。通用套餐、版本化报价、购赠比例、先到期先用、订单资金组合、交付、续费授权、促销、KOL 让利、佣金、提现、采购和补货已接通。采购价格与调用价格分开；采购成本移动加权平均；超卖仅扩大可售承诺，采购不足仍停止调用。到期购买价值推动确认支出资格，不产生调用佣金。

**模型服务。** 平台统一维护公开模型、供应商密钥、能力、路由和分层授权，经营方独立定价。受理时固定零售及各层批发快照，原子占用客户和采购责任，按可靠用量结算。多个 Key 共享账户额度，自然周期预算不划拨资产。同步、流式、异步和网页体验共用计费；失败尝试、用量未知、超额、幂等回读、路由健康与恢复均有实际处理路径。Key 创建、预算查询和受理统一使用数据库业务时钟。

**资金处理。** Stripe、支付宝、微信、NOWPayments、自有钱包只读 EVM 核验及线下登记均有具体实现；材料不足时保持待配置。收款、估值、订单分配与交付分离。原币到账但无法核实实际付款时点估值时，保留原币责任并进入财务待办，不凭下单汇率制造 USD。退款责任、原执行指令、部分实付、新目的地授权、通道费用及迟到事实分别追踪，防止重复清债。系统不发起银行或链上提现转账。

**责任和接管。** 普通套餐不自由退款；错误扣费、支付余额退回、异常履约退款、外部扣回及错误佣金按原来源处理。渠道接管清理在途责任、复核快照、一次作价抵扣采购、原子承接客户权益与推广链，双方差额独立结清。原 Key 继续服务，接管后收益与风险归品牌。关闭客户或经营方时，所有历史订单的待估值原币及已收未分配款仍是未结责任，不能借关闭订单绕过。

**门户和运营。** 客户工作台、经营后台、合作管理、平台技术管理、通知、报表、开票申请及私有文件、对账和导出已接入。经营表单使用有权限的引用选择器和版本管理。OpenAPI 198 条路径、177 份 Schema，111 份经营写入元数据都有明确 DTO 和自动漂移检查。前端金额以十进制字符串处理，显示近似值不改变提交与结算精度。

**运行基础。** 新库代际为 `tokenhub-operator-v2`，迁移命令独立执行并检查校验和。API/worker 就绪检查不自动迁移。持久任务租约、fencing、重试、失败待办、事务 outbox/inbox、Redis 限流、私有结果加密及到期删除、指标访问限制、备份和隔离恢复已实现。普通 API 内容不长期保存；同步回读默认 5 分钟，异步结果默认 24 小时。

## 实际验证结果

后端采用全仓 `go test -race -p 1 -count=1 -timeout 15m ./...`，修复发现的问题后整组复跑受影响的 commerce、payments、usage、portal。合并最新结果：**22 个有测试包、239 个顶层用例通过（含子用例共 308 项），无未解决失败**。持续负载另行显式运行；worker helper 由父用例作为真实子进程启动，因此这两项在普通入口跳过，不算作本轮新通过。最终受影响包耗时分别为 commerce 52.548s、payments 6.160s、usage 106.508s、portal 73.269s；签名回调综合用例实际通过，没有因缺少旧环境变量而跳过。原始失败记录及复跑结果均保留在 `integration-lab/evidence/final-regression-20261016.json`，未把最初失败命令写成成功。

- 前端生产构建、TypeScript、12 项 Vitest、7 项 Playwright 契约测试通过。另有不拦截请求的实际 Chrome 走查：邮件注册、协议收款、余额购包、创建 Key、Bifrost 调用、网页体验、账单、票据上传下载、独立补偿、稳定币待估值恢复及部分退款后更换授权路径完成清偿。
- 四条销售链通过真实 PostgreSQL、Bifrost HTTP 和私有 S3 联调，逐层核对独立价格、采购扣减、实付基数、佣金、导出权限和对账；逐边采购不足拒绝调用，其他占用回滚。接管后原 Key 调用也已实际验证。
- 独立协议服务覆盖普通及多模态 HTTP、SSE、异步任务、未知提交、签名回调、重复和迟到事件、部分支付/退款、只读链上证据及 SMTP。应用业务未嵌入假支付或固定模型结果。
- 30 分钟混合负载完成 **39,914 次调用、23,474 笔购包**；两倍并发冲击完成 **4,588 次调用、3,383 笔购包**。两组失败、重复上游尝试、未完成请求和账差均为零。这是共享开发机上的单账户热点测试，存在明显排队，不作为商业吞吐或整体平台延迟达标证明。
- 真正的独立 worker 进程在提交前、提交后确认前分别被 SIGKILL；替代进程等租约到期后恢复，业务效果各只有一次，旧 fence 不能提交。
- 实际 pg_dump 和加密归档恢复核对高精度余额、占用、分录及待办一致；长期文件恢复，临时结果和导出排除；损坏备份和已有目标均拒绝覆盖。恢复不自动启动 worker。
- 最终 Docker API/worker/Next 镜像已重新构建并在隔离环境启动。实际 HTTPS 首页、两条业务代理入口与就绪接口返回 200；公开 metrics 返回 404，未授权内部 metrics 返回 403；本地 CA 链和主机名验证通过，未登记 SNI 握手被拒。结果及镜像摘要见 `integration-lab/evidence/runtime-tls-final-20261016.json`。
- OpenAPI 生成结果及全部引用校验、部署隔离检查、MinIO 失败恢复脚本、`git diff --check` 通过。

最终回归曾发现并修复：Key 使用主机创建时间而受理使用数据库时间造成刚创建即不可用；支付事实回放复用 JSON 缓冲导致后续请求证据损坏；经营概览缺少未结责任查询所需事务。销售发票测试夹具也统一到数据库时间。以上不是用跳过失败测试处理，修复后对受影响包整组复跑。

## 验证边界与启用条件

本轮所有数据库、Redis、对象桶、协议服务、邮件收件人和财务事实均为隔离合成环境。保留原 `.env` 链接和运行数据；未向真实客户发邮件或发起真实资金转移。

按照用户关于外部材料的决定，真实供应商 Key、商户账号/证书、网络资产及 RPC、换汇估值资料、邮件域名、Cloudflare 账号和公网 DNS/TLS、法定发票办理须在资料齐全后配置和实测。新供应商还须核实模型能力、参数、用量和费用上界。这里的协议通过不等于商户开通或真实资金结算通过。

全部已确定功能均在实现范围内，没有按“第一版”裁掉功能；浏览器证据覆盖关键闭环，没有对全部 135 项逐一重跑所有角色和状态排列。领域、HTTP、协议、浏览器、负载和运行证据应合并阅读，不能互相替代。正式部署还须配置异地备份副本、独立密钥保管，并在目标硬件及真实业务分布下确认容量。
