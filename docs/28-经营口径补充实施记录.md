# 经营口径补充实施记录

依据用户 2026-10-10 最新决定；本记录只覆盖本批经营实现。整合后全项目验收由根代理记录在 docs/26、docs/30。

## 已确认口径与实现

- 平台与 OEM 各算自身经营收入、成本与毛利。OEM 终端消费 150、按平台结算价实际消耗 100，OEM API 毛利为 50。
- OEM 采购预付 1000 是现金与服务库存事实，不再扣为本期 API 成本。平台实际收款且原 OEM 服务额度到账后，该笔服务销售即完成；平台销售额取协议金额，不等终端调用、不拿额度面值替代收款价值。
- 平台营业收入＝官方品牌（含直属渠道）自营净消费＋已完成 OEM 服务销售净额。OEM 终端 150/120 的售价变化不改变平台收入。平台实际成本读取原供应商 `billing_cost_entries`，包含已经发生的失败尝试成本。
- OEM 消耗成本只取原 `billing_customer_charges.usage_event_id` 关联的 committed/reversed 计费事实对应平台结算金额。旧非零 pending 计量被替换并标 voided 后，没有原计费事实，不能重复计成本。
- 客户消费冲正撤回收入，不自动抹去已经发生的平台服务成本或供应商实际成本。现金供应商付款、采购协议金额、额度库存另外列示，均不再重复扣减 API 毛利。
- 营销按原品牌及其直属渠道完整汇总，API 经营利润＝毛利＋营销净额（支出为负）。平台工作台、经营汇总、经营维度和日报使用上述平台口径；有权排障的原技术统计仍保留。
- 无收款的管理额度调整不自动生成销售。已有测试数据中没有采购关联的旧增额不猜测为收入。

## 采购与误录更正

新增 `billing0018_oem_purchases`、`billing0019_oem_purchase_reversals`。登记人必须是平台管理/财务岗位，确认实际收款，提供原 OEM、金额、币种、发生时间和服务额度；真实交易号与内部说明可选。

收款登记、销售事实、服务额度划入和审计共享一个数据库事务。持久 operation 绑定登记人、OEM、金额/币种、额度、时间及可选内容；并发与未知结果重试回到原单，不重复增额。查回暂未找到仍保留原操作。非空真实交易号防止重复有效登记，409 提供原记录供核对；明确拒绝后可主动结束原操作。分页游标与 OEM 列表使用相同主体范围；OEM 看不到平台内部说明及内部登记人标识，渠道没有采购写入口或独立资金池。

误录更正仅按原单执行：必须能从原 OEM 当前尚未发放的库存全额收回原服务额度；否则拒绝且不改销售、客户钱包或额度。撤销原因、原单、反向额度流水、销售冲减、时间与审计原子保存，原款项/币种/金额不覆盖，平台和 OEM 都能查看已撤销事实。撤销不是银行退款或外部资金追回。原有效交易号在误录撤销后允许用于正确重新登记，原单仍保留。

前端保留待确认 payload 与同一 operation；重新打开、查询、重试均核对原内容。响应中的金额或主体不一致不能显示本次成功。撤销同样保留原 operation 与原因，并允许查询原单确认最终状态。

## 接口与金额单位

| 接口 | 范围/用途 |
| --- | --- |
| GET /admin/oem-purchases | 平台 P/F/O/审计读销售记录，支持 OEM 范围及 cursor |
| POST /admin/oem-purchases | 平台 P/F 确认实际收款并划入额度，含确认头 |
| GET /admin/oem-purchases/operations | 平台 P/F 查本人、原 OEM、原 operation |
| GET /admin/oem-purchases/:id | 平台 P/F/O/审计读原记录，包括撤销事实 |
| POST /admin/oem-purchases/:id/reverse | 平台 P/F 撤销误录，原单/operation/原因及确认头 |
| GET /channel/oem-purchases | 当前 OEM 本品牌只读；foreign cursor 404、渠道 403 |

`cash_amount_minor` 是原现金币种：USD 为 microUSD（1 USD＝1,000,000），CNY 为分（1 CNY＝100）。`sale_amount_minor` 与 `quota_amount_minor` 始终为 microUSD。USD 实际收款与协议销售额一致；CNY 需要明确填写已约定的 USD 价值，系统不猜汇率。金额在页面分别标明原币种与 USD 服务价值。发生时间由操作者提供，交易完成时间由系统生成，页面显示 UTC+8；经营日报沿用 UTC 日期分组。
