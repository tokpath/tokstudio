# 上线前角色验收与放行清单

更新：2026-09-21。代码分支：`release/v0.1.0`。

本次工作从人的操作链路出发，使用 OrbStack 独立本地环境及真实浏览器登录，辅以隔离数据库的接口、事务故障、并发和权限测试。测试账号、模拟消费和模拟收款凭证均不代表真实资金收付。逐次证据与日志保留在仓库并列的 `../local/`，不提交远端。

支付商户材料及真实上游凭据尚未准备好。因此本报告是本地产品验收和代码整改结果，不是生产支付、真实模型可用性或生产容灾的通过证明。放行前仍须完成文末外部验证。

## 角色及任务覆盖

| 角色 / 入口 | 已进行的人工链路 | 自动化补充与边界 |
|---|---|---|
| 访客、普通用户 `/app` | 登录/退出、注册归因、创建 Key、余额不足的试用反馈、接入地址与文档、钱包余额/赠送、支付未开通、推荐、越权访问返回、手机导航、钱包中英日切换 | Key 白名单/限流/轮换、三桶账务、媒体失败释放、请求重试、隔离及接口错误由回归覆盖；真实上游与真实收款待材料 |
| 平台管理员 `/admin` | 用户筛选→填写原因→封禁/解封；渠道详情/额度核对；管理员交接→本人登录→撤销；模型异人审核发布；路由修改与恢复 | 审计失败回滚、跨角色/跨渠道拒绝、重复授权不重复、已有会话撤权、渠道品牌和默认模型继承 |
| 财务 `/admin` | 搜索赠送用户、赠送有效期、充值确认/退款、消费退款、佣金结算、模拟打款、付款后冲正、部分追回→全部结清、重算无变化/退款不恢复 | 金额和凭证精确、重复/并发仅一次、钱包/营销/结算同事务，注入失败后重试；真实外部支付未执行 |
| 运营 `/admin` | 低价渠道套餐审核；创建模型→自审被拒→另一账号通过→单独发布→弃用 | 创建人不能自审/自发布；无提供商/价格的模型也能正确弃用；价格保留旧快照、权限规则由回归覆盖 |
| 技术 `/admin` | 沙箱探测、真实提供商不支持探测提示、路由确认/保存/恢复、告警评估与手册入口 | 不再把 TestBehavior 当作真实上游探测；真实上游主动检查与实际可用性仍需联调 |
| 审计只读 `/admin` | 账务没有写按钮，审计读取权限交接、路由、退款和追回记录 | 新增时间、操作人编号、请求号与可展开变更内容；写接口拒绝由权限测试验证 |
| A 下 B `/channel` | 登录/退出、用户管理与本渠道经营页面；创建套餐被拒 | 继承 A 品牌套餐与售价，模型授权、独立池、商户权限及账本回归 |
| OEM C `/channel` | 创建下属 B、逐级授权模型、制定/发布本品牌套餐、向 B 划拨、品牌和经营账本 | C 只能建 B；新子 B 继承品牌但无初始模型授权；C 与子 B 使用 C 分佣规则，B 保持独立池 |
| C 下 B `/channel` | 平台授权已注册接手人→登录→仅见本渠道用户→核对 $10 独立池→无建下级入口→规则只读→支付未开通→撤销临时授权 | 权限授予与审计同事务、跨租户拒绝、授权不改归属；测试创建的旧 B 保留历史配置，不能作为新继承逻辑的证据 |
| 代理商、推广员 `/partner` | 邀请/注册归因、范围查询、两跳收益、冻结/解冻、退款冲正、打款及追回历史、个人钱包和推广范围核对 | 原始收益/反向记录关联、当前策略不覆盖历史、正确重算不改金额或冻结期、后续收益不擅自抵扣欠款 |

上述“人工链路”仅表示表中实际操作的场景；自动化用例与沙箱结果不冒充所有生产组合的人工验证。

## 问题与整改结果

| 问题 | 整改 |
|---|---|
| 跨门户退出、归因导航、接入端口、未登录/越权误显示空后台 | 统一账户菜单、导航/地址解析、访问守卫及可恢复错误态 |
| 财务裸金额和默认值易误读，对象与后果不清 | USD 输入展示、检索业务对象、明确确认摘要；去掉重复的裸充值单操作，转至支付订单页 |
| 赠送/消费退款/佣金生命周期存在重复和部分提交风险 | 事务锁、原始凭证、成对冲正、故障回滚及并发幂等；打款出账、追回登记不重复扣 API 钱包 |
| 重算先冲正后失败，或按当前策略覆盖旧账 | 原策略快照及版本保留；只修正冻结差额；无差异不修改；缺快照/已发放差额明确转人工核对 |
| 用户管理默认封禁原因、失败信息不易发现 | 先选人再填原因，确认显示邮箱/后果，错误留在弹窗，状态/列表可刷新 |
| 模型弃用已生效却报错，自审拒绝信息藏在弹窗后 | 移除下架对价格/映射的不合理前提；失败提示放入确认框；创建摘要包含目标 |
| 路由确认无目标与新值、真实探测误报正常 | 展示路由及新策略；非沙箱探测明确不支持且不改健康值 |
| 用量显示内部整数、真实用量补录带默认 Token | 按美元和中文状态展示；默认留空、校验整数、确认真实请求/数量；原消费与退款状态分开说明 |
| 渠道/推广首页堆叠所有表单 | 总览及任务入口，明细和操作进入对应专页 |
| 渠道创建后无法交接管理员、子 B 默认范围错误 | A/C 按直属渠道注册邮箱授权/撤销并审计；新建子 B 只继承父品牌，模型须显式授权；品牌目录按 A/C 选择 |
| 审计缺时间和变更凭证，列表加载像空数据 | 增加可核对字段及展开详情；区分加载、失败和真正空态 |
| 恢复脚本删除已有目标且吞掉失败 | 只建新隔离库，失败非零退出，事务恢复后检查迁移表/应用表；已有目标及损坏密文拒绝 |
| 已知依赖安全公告 | 升级修复版本并重跑单测/构建/端到端/后端；扫描边界单列，不以测试通过替代安全扫描 |

## 历史数据核对

执行只读 `scripts/prelaunch_reconciliation.sql`，输出钱包与净凭证差异、已付款与出账凭证、缺策略快照的有效佣金。报表不写数据；导入或期初余额应结合原始凭证解释，不能仅凭差异自动补账。

本地只发现已记录的旧测试异常：测试钱包余额与凭证相差 $5；旧 `LOCAL-TEST-SETTLEMENT-20260918` 的 $0.30 模拟打款缺出账。新 `LOCAL-CASH-PAYOUT-20260918` 出账 $0.30 与原单一致，追回两笔合计 $0.30、余额为零。历史异常没有伪造凭证或自动改余额。

实际业务库上线前亦须运行该报表。若存在异常，财务按原始收付款证据确认处理方案，保留调整依据及成对流水。旧 C 下 B 的品牌和模型授权应按合同逐户复核，不全库强制改写。

## 本地恢复及发布检查

- 已从已有加密备份真实恢复至新隔离数据库，恢复出 74 张应用表；已有同名目标拒绝，损坏密文拒绝。恢复库保留作复核。
- 本地恢复不等于生产 PITR、异地存储可用性或达到 RPO 15 分钟 / RTO 1 小时。页面逻辑演练只能证明连接与迁移检查。
- `scripts/assert_deploy_isolation.sh` 通过。此检查不连接生产主机、不执行发布。
- 最新前端和后端结果、提交及 CI 链接在 `../local/acceptance.md` 记录；生产部署必须使用最终 CI 通过的提交。

## 材料齐备后的放行步骤

1. 在目标环境注入商户、回调域名、证书及上游凭据，避免通过聊天或仓库明文交付。检查没有启用开发种子账号和测试密钥。
2. 每个实际收款渠道分别完成小额支付→可信回调→入账→重复回调不重复入账→退款→用户/渠道/平台对账，并核对异常恢复。
3. 每个准备售卖的模型分别完成真实文本/流式或媒体任务，核对提供商、实际用量、超时/失败释放、路由回退与价格快照。未完成接入的目录项不能当作可调用商品宣传。
4. 在目标基础设施验证域名/TLS、对象存储、邮件/OAuth（若启用）、外部回调可达性及生产备份恢复/PITR，记录实际恢复耗时和数据点。
5. 运行历史对账报表，确认渠道管理员交付、权限回收及财务异常处理；保留最终 CI、回滚版本和验收证据后再执行生产放行。
