# T07 佣金结算与财务事实整改

基线 `fd7c5f8`，工作分支 `codex/commission-workflows`。已 fetch `origin/release/v0.1.0`（`64e1825`），工作分支不落后。当前只做本地实现与隔离数据库测试，不外部转账、不推送或部署。

## 核心批

- 平台与 OEM 共用佣金工作区，默认待结算，分开待打款、待收回、全部佣金、低频规则。状态、服务器搜索、翻页、推广归属及 `next/from` 保留在 URL。列表与原操作按本人、真实品牌资金主体隔离，服务端重新鉴权；渠道旧入口只展示本人收款角色的真实佣金与结算，不复用额度发放记录。
- 结算预览读取当前政策与完整候选，展示生成账期、实际佣金发生范围、条数、人数、各收款角色金额、冻结/暂停/未达最低额等排除事实。维持原“全部当前可结算记录”算法，生成账期不是强行过滤消费月份。预览限时10分钟；提交在原生命周期事务锁内重新核对当前政策和候选指纹，变化返回409重新预览。政策修改取得同一生命周期锁，不改变历史计佣快照。
- 新结算保存完整原始成员 ID。撤销后未冲正成员再结算，原单详情仍能检索原成员。历史单没有完整快照时明确标记，不能推断不存在的原始成员。
- 打款固定原单金额，填写实际发生时间、确认已实际打款，参考号与内部说明可选。佣金钱包扣减、单/成员状态、打款事实、操作结果与审计在同一事务提交。内部记录 ID 与真实外部交易参考号独立；空参考号与重复说明合法，非空真实参考号在品牌内防重复，包括能归属当前品牌的历史记录。钱包不足保持原单待打款，不造成负余额。
- 追回支持分次实际到账，只收回大于零、不超过剩余的金额；不变更 API/积分/佣金钱包，不自动抵扣未来佣金。保存实际发生时间、系统登记时间、操作人、可选参考号和说明，按原结算所属品牌授权，不能因收款用户当前归属改变而越权。
- 结算、打款、解冻、追回操作保存同主体稳定操作 ID 与原参数，返回原结果；同 ID 改参数冲突。前端在提交前保存原单，未知网络/500结果跨关闭、重载保留；后续409或临时404不清除原单，只回查/重试同一操作。明确成功与列表刷新独立，不把刷新失败重新判为登记失败。
- 完整列表不再截最近100/200后做本地搜索。服务端先鉴权、搜索完整事实，按 `created_at,id` 游标返回分页与完整匹配条数；153单真实 HTTP 回归覆盖第101+及最老记录。现有实现在应用层筛选完整授权结果；若数据量继续增长，可保持本契约换成 SQL 搜索与分页。
- 只读岗位保留详情与原始事实，无可写表单。详情采用受控弹窗，关闭返回原触发按钮。规则确认显示原值→新值、当前品牌、版本、冻结期和最低额，保留原百分比/BPS语义。
- 旧 `/channel/rules` 转佣金规则；OEM `/channel/commissions` 转资金流水划拨；OEM `/channel/settlements` 转待打款；渠道保留本人佣金/结算只读。重新鉴权且保留返回与查询上下文。
- 提供 `Commission.RequestFacts(ctx,requestID)` 独立只读方法供 T08 在先鉴权请求后读原佣金事实。收款身份字段为 `beneficiary_role_id`，不是消费者当前推广角色。管理/OEM原单链接：`/admin/commission?tab=payout&settlement_id=...`、`/channel/commission?tab=payout&settlement_id=...`，即使单已付款也能打开。

## 迁移和历史口径

新增 `commission/0004_workflow_facts.sql`、`billing/0015_recovery_workflow_facts.sql`。实际发生时间留空表示历史未保存，不以系统登记时间伪造。历史参考号/金额/操作 ID/钱包/政策版本不重算。内部旧服务接口保留受信任调用兼容，公开资金写入口必须提供真实新事实。新界面不自动转账；欠费、追收、抵扣业务没有新增。
