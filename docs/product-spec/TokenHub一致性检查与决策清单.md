### 账务守恒约束

实现中至少同时保持以下关系：

- 每笔真实收款的已分配金额不超过可分配金额；已经退款或扣回的记录按事实关联，不能假设仍可分配。
- 每个资产余额都能由入账、实际消耗、到期、退款和冲正等记录解释；占用是可用性约束，不凭空增减资产总量。
- 一笔套餐实付的已消费归属、有效未用归属、到期归属和已退款归属互不重叠，其合计可与原实付核对。
- 每次额度扣减的购买和赠送来源之和等于实际客户扣减；经营方承担缺口单列。
- 资格统计使用已确认的消费及到期归属；佣金只使用符合资格条件的实际有偿调用归属。
- 佣金钱包的冻结、可用和占用不得重复相加；待抵扣是独立待处理项，不能直接扣其他资产。
- 采购数量和账面成本守恒；现金退款价值与账面成本的差异单列。
- 内部重试、重复通知和任务状态查询不重复生成外部交易、权益或费用。

为避免公式失效，实付为正的套餐必须包含正的购买额度。无实付赠送不产生有偿基数。此校验是购赠公式的成立条件，不增加新的收费或营销制度。

以下事项需要明确配置值或技术实现，但不构成新增主干业务选择。业务参数不得通过代码中的隐蔽常量替代；需要对客户展示的条件应在生效前公布。

| 批发购买报价、差异化优惠、退出可退条款 | 直接供货方与采购方 | 采购时明确；不能追溯取消旧报价承诺 |
| 手动价格、自动跟随倍率、模型促销 | 对应定价经营方 | 有生效时间，提前通知，受理价快照保留 |
| 渠道超卖额度 | 品牌方 | 不构成采购授信，变化重算风险，已售权益保留 |
| OEM 自身超卖安排 | OEM | 自负责任，不扩大平台供货义务 |
| 补货阈值、单次及周期上限、报价授权 | 采购经营方 | 明确授权，各供货层独立，失败不垫资 |
| KOL 门槛 | 客户所属经营方 | 提高保护既有资格，降低让达标者受益 |
| 直接和间接佣金比例 | 客户所属经营方 | 订单固定；与让利共同保证直接净比例不为负 |
| 消费确认期及共用佣金冻结机制 | 客户所属经营方 | 适用事件保留版本，不能追溯延长待确认事件；争议另处理 |
| 邀请与注册赠送数量、期限和适用条件 | 客户所属经营方 | 正式注册事件按规则执行，履约及次数预占，重复事件幂等 |
| 活动适用条件、次数、限量及并用许可 | 对应经营方和有权 KOL | 经营方约束范围内配置，订单结果固定 |
| Key 预算、模型和频率并发限制 | 客户 | 不划拨资产，按自然周期和账号池校验 |
| 经营时区及其显示 | 对应经营方的服务配置 | 统一展示；历史受理窗口和已生效期限不因配置变动重算 |
| 提现最低金额、方式、费率和办理安排 | 客户所属经营方 | 申请前展示，USD 费用申请时固定，原币汇率不锁 |
| 预警阈值、接收人、重复及升级间隔 | 相关经营方 | 进入超卖前有有效预警，关键业务通知不能当营销退订 |
| 正常变更提前通知期限 | 有权变更方的公布规则 | 需要重新授权的事项不能因通知期届满自动视为同意 |
| 渠道接管触发、授权及作价方法 | 品牌方与渠道 | 事先约定，完整承接客户权益，客户不承担双方缺口 |
| 复核事项、金额阈值和角色授权 | 各经营方 | 按需配置并完整审计；启用独立复核时不可自审 |
| 支付通道、稳定币与网络组合 | 平台接入及经营方启用 | 以实际接入能力为准，商户独立收款，原币及 USD 对账 |
| 模型接入、路由健康与安全重试 | 平台 | 验证计量、能力及采购上界，不降低已承诺请求要求 |
| 请求执行及用量核实期限 | 平台技术配置及公布规则 | 有界占用，超时不可靠用量不收费，不日后追扣 |
| 异步结果暂存与脱敏记录保留期限 | 平台技术及对应服务规则 | 明确展示，不引入长期内容保存功能 |
| 数值精度、来源分摊顺序、幂等保留窗口 | 技术实施方案 | 满足小额累计、来源追踪、历史稳定和资产守恒，不改变商业基数 |
| 开票环节、资料和金额 | 实际交易经营方 | 外部正式开具，系统登记，防止重复超额与事实不符 |

来源分摊等确定性细节可以采用清楚可复现的默认算法，但必须写入实施方案并通过相关验收。不得自行新增“自动抹零”“充值直接达标”“固定历史汇率退款”等与已确认规则相反的默认行为。
