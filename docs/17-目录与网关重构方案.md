# 目录与网关：定型方案

日期：2026-09-28。产品未上线，旧目录配置可清理；已结算用量快照保留。

## 一个对象只管一件事

| 页面 | 保存的事实 | 生效条件 |
| --- | --- | --- |
| 提供商 | 连接、账号池、支持的上游模型、各模型成本价 | 能探测则从上游模型接口读取；无价格接口则人工补价 |
| 模型 | 名称、不可变调用 ID、类型、说明、公开售价 | 填全自身信息即可发布；发布不等于可调用 |
| 路由组 | 一个公开模型对应哪些提供商模型，以及顺序、权重、健康或参考成本策略 | 候选上游模型必须有该类型的成本价；启用后才可转发 |
| 渠道授权 | 可用模型白名单、渠道结算价、可选的该渠道客户价 | 已发布且有有效启用路由才可新增授权 |

使用顺序：配置提供商及上游报价 → 创建并发布模型 → 创建并启用路由组 → 授权渠道 → 客户调用。各页可独立准备；不要求在模型页和路由页之间往返发布。

## 页面原则

- 新建模型、提供商和路由组直接进入完整表单页；不先填弹窗再补详情。模型创建一次录入自身信息和首次售价，后端生成调用 ID，保存草稿，确认后发布。
- 新建提供商只填名称，内部标识由后端生成。提供商详情显示上游模型清单和输入、输出、图片、视频、音频成本价。人工添加只填真实上游调用标识，显示名默认相同；探测只写提供商清单，不创建公开模型。探测不到的模型和报价由管理员补齐。上游模型可停用，停用后路由和网关均不再选用，重新探测不会自动启用。账号池是唯一密钥入口。
- 路由组的上游模型为选择器，只列当前提供商已配置该模型类型成本价的模型。后端同样校验，避免绕过页面提交。
- 渠道授权时录入渠道结算价；客户价留空则使用模型公开售价，填写则只覆盖该渠道。撤销授权后立即停止新调用。
- 价格版本只显示公开售价。成本与渠道价格分别在所属页面维护。

## 网关与账务

- 请求先用模型售价与渠道客户价计算预留额度。路由在有效、已定价的候选中选择；“选更便宜的”按上游模型参考成本排序。
- 成功转发后，把**实际选中的提供商模型成本**、渠道结算价、最终客户价写入本次用量快照。成本、毛利和渠道结算只读该快照；后续改价不改旧账单。
- token 单价可低于一个 micro-USD；先按完整用量相乘，再统一舍入，避免低价模型成本变成零。缺成本的候选不可接单，不用估算折扣或旧模型全局成本兜底。
- 数据迁移删除目录价格版本里的旧上游成本、批发价、渠道覆盖价及旧提供商价格版本，并清理无渠道结算价的旧授权与无成本的旧路由候选；候选清空的路由组自动停用。保留模型目录、路由组和已结算用量与资金流水。目录快照导入不自动授权，也不覆盖人工修改。演示提供商报价和渠道价改为各自独立的种子数据。

## 验收

1. 提供商探测、人工补价后，路由页出现该上游模型；未补价时前后端均阻止选入。
2. 模型公开售价不含提供商成本；渠道价只在授权页配置。
3. 同一公开模型切换到不同成本的提供商时，结算快照记录实际选中者，参考成本策略选择更便宜者。
4. 改成本或渠道价只影响新请求；历史账单和快照不变。
5. 完整走通创建模型、发布、配置路由、授权、调用、停用，并通过 Go、Web 与浏览器检查。
