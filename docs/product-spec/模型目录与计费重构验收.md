# 模型目录与计费重构验收（2026-10-22）

## 最终产品结构

公开模型管理名称、能力和开放状态。供应商管理连接、密钥、供应商模型和能力，并可选择 Bifrost 参考成本模型；不再要求填写用量字段路径、计费公式或逐能力供应商报价。路由将一个公开模型绑定至多个供应商模型，支持优先级、观测延迟和估算上游成本策略。

平台在“模型与定价”配置公开模型的输入、输出计量项目。每个方向选择统一 Token，或按文本、图片、音频、视频分别选取计量方式。统一 Token 不能与该方向的其他模态项目叠加；同一模态不能重复配置。经营方只为系统列出的项目设置 ATG 价格，零售与批发独立定价。套餐与供货报价继续决定 USD 换取多少购买及赠送 ATG。

缺少可靠模态拆分时，不把包含图片或音频的总 Token 当成纯文本 Token 再叠加媒体费用。需要统一 Token 的模型必须明确采用该合同；已受理的调用不会临时切换计费口径。图片数量、像素、字符及媒体时长取自已适配的标准协议和可核实的文件元数据，不开放任意字段映射。需要输入物理计量却无法核实的请求在转发前拒绝并释放占用；能够由供应商返回已处理时长的转写可在完成后核实。不可核实的实际用量依确认期限处理，不能猜测扣费。

Bifrost 设置提供当前组件版本、自动同步、同步间隔、来源与结果。默认每 24 小时同步，失败保留上次成功价目。升级依赖和定时同步是两个独立动作。参考成本在调用受理时保存快照；可靠的上游 USD 报告优先，其次采用 Bifrost 核算。未知成本保留未知，不冒充免费。

“真实上游成本”只登记供应商、可选模型、期间、实际 USD 和备注，与同范围核算金额并列展示。不会改客户账单，不引入折扣分析、自动调价或复杂对账业务。

## 已验证的关键流程

- 浏览器完成密钥创建与轮换、供应商模型创建、公开模型创建与修改、路由绑定与修改、零售和批发价格发布、授权及上架，最终由客户创建 Key 并调用独立 HTTP 模型服务。重试同一幂等请求没有二次扣费。
- 浏览器配置“输入文本 Token + 输入图片百万像素、输出文本 Token”，完成 Bifrost 24 小时同步设置与手动同步、真实成本登记与修改，并切换中文、英语、日语、俄语。
- 外部 mock 独立部署于仓库之外；真实 PostgreSQL、Redis、S3 与 Bifrost 参与联调，覆盖文本同步和流式、Responses、Embedding、图片、语音合成、转写及视频异步任务。
- 集成验证四条销售链、渠道接管后的后续调用、预占与实扣、客户费用与上游成本独立入账、成本快照、未知用量及错误重试。不可计量输入立即释放占用，且不误触供应商熔断。
- 计量边界包括：混合输入不重计、缓存不重复计入普通输入、输入图片重复提交按实际份数、转写按已处理时长、流式字符累计、图片完成事件计数、视频不采用 SDK 请求回填时长、MP4 不把媒体内容误作元数据、包含输入的音频总时长不冒充输出时长。

## 验证结果与范围

后端完整 `go test -race -p 2 ./...` 通过；最终边界修正后另行回归运行时、成本与调用账务相关模块。前端 30 个文件、239 项测试通过，生产构建通过。普通浏览器回归 27 项通过，112 项依赖专门验收环境的用例按配置跳过；以上两条新增业务浏览器用例已在真实隔离应用上单独执行通过。OpenAPI 生成一致性和 13 项契约测试通过。

本次没有清除已部署测试环境的数据。外部联调使用合成供应商和支付事实，不能等同于真实商户或真实供应商的生产联调。计量仅对已有协议适配和可核实格式开放；新增供应商的特殊用量协议仍须增加适配并验证，不能依赖运营人员猜测字段。
