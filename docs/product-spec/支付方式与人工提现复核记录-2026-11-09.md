# 支付方式与人工提现复核记录（2026-11-09）

用户本轮纠正了此前过度设计。本记录以本轮明确要求为准：将原佣金提现、余额提现的方式和手续费规则挪到“支付方式与手续费”，不重新设计提现流程。

- 保留方式选择、启停、适用业务、固定金额或费率。余额与佣金提现共用规则，收款费用仍按此前确认的方案共用。
- 删除额外增加的提现到账币种、兑换比例、网络开关、办理说明和资料预览；客户沿用原收款资料模板，按原流程申请、审批及登记付款。
- 未添加方式时不显示任何支付方式卡片，“线下支付”与其他方式一同在添加下拉框选择。线下支付内置，无需填写收款信息、付款说明或选择“线下办理”。KVoucher 移除无实际用途的线下退款方式及其校验；异常退款保留。
- 收款只有实际线上连接需要填写凭据。提现无需线上商户接入。Stripe 只用于收款，现金归入线下支付。
- 规则修改仍校验费用版本；提交结果不明时复用同一内容与幂等编号。已提交申请的金额、手续费、资料和付款事实不重写。
- 迁移撤销上一版配置迁移对支付宝、微信、USDT 提现的自动停用；若经营方之后自行调整，尊重其选择。无关账号、资产及其他配置不清除。

验证：前端 375 项测试、类型检查、生产构建和 25 项接口契约检查通过；真实 PostgreSQL 下的提现、手续费、历史配置迁移和页面接口回归通过。浏览器使用隔离数据库与真实 API，完成平台配置、充值入账、余额提现申请、审批、登记付款，并核对佣金提现共用规则、OEM/渠道独立设置、四种语言及手机布局。真实外部商户支付不在本次验收范围。
