# TokenHub 业务说明

状态：草案，供直接修改。本文只写业务，不写实现、页面路径和历史迁移。

TokenHub 把多家模型供应商收成一个服务。终端用户使用一个地址和一把 API Key 调用模型。用户选择模型，不选择供应商，也不选择内部路由。

全库只有一个平台。平台经营自己的品牌，也可以开通 OEM、发展自己的渠道。OEM 在经营上是另一个品牌，技术上使用本平台的模型服务。渠道负责推广，不经营品牌，不收款。

## 1. 三种组织

| | 平台 | OEM | 渠道 |
| --- | --- | --- | --- |
| 数量 | 只有一个 | 可以有多个 | 挂在平台或某个 OEM 下面 |
| 经营 | 经营官方品牌 | 经营自己的品牌 | 不经营品牌 |
| 可以建立 | 渠道、OEM | 只能建立渠道 | 不能建立下级 |
| 模型供应 | 接入供应商、维护目录和路由 | 只使用平台已经授权给自己的模型 | 只使用所属品牌已经授权的模型 |
| 套餐 | 制定并发布官方品牌套餐 | 制定并发布本品牌套餐 | 不能创建、发布或下架套餐 |
| 收款 | 收官方品牌的款 | 收本品牌的款 | 不收款、不划拨额度 |
| 利润 | 算自己的经营 | 算自己的经营 | 只看本人推广收益 |

OEM 不能再建立 OEM。渠道创建后继承上级品牌，组织类型和品牌归属不再更改。

平台协助 OEM 配到可以营业，然后交给 OEM 日常经营。协助交付不使平台变成该 OEM 的收款方。平台不代替 OEM 创建、停用或交接 OEM 的渠道，这些渠道也不出现在平台的日常管理里。

## 2. 品牌、模型和价格

一个品牌一套终端售价。平台定官方品牌售价，OEM 定自己的品牌售价。渠道不单独定价，也不持有库存。

平台维护供应商、上游模型和路由。模型对用户公布的是公开模型。OEM 和渠道都不能自带供应商密钥，也不能新建公开模型。

授权向下传递：

- 平台把模型授权给官方直属渠道，也授权给 OEM。
- OEM 只能把自己已经获得、且已上架的模型，再授权给自己的直属渠道，也可以撤销。
- 渠道可以在已授权范围内自行下架。渠道不能越过上级的撤销，自行把模型重新上架。
- 平台把某个模型全局下架后，所有品牌都不能再使用它。

## 3. 套餐

套餐是品牌卖给用户的一包额度。平台一套目录，每个 OEM 各一套目录。

名称只在同一份目录里不能重复：

- 平台套餐之间不能重名。
- 同一个 OEM 的套餐之间不能重名。
- 不同 OEM 可以同名。
- OEM 套餐可以和平台套餐同名。

比较时忽略大小写和名称两端的空格。

每个套餐有售价、包含额度、额度周期和适用渠道。

额度周期有四种：

| 周期 | 含义 |
| --- | --- |
| 不限时 | 买到的额度不过期，不自动续费 |
| 每月 | 按月补充额度 |
| 每季 | 按季补充额度 |
| 每年 | 按年补充额度 |

适用渠道有两种：

- 所有渠道：这个套餐卖给本品牌下的全部客户。平台套餐指平台下的渠道；OEM 套餐指该 OEM 下的客户。
- 指定渠道：只卖给点名的直属渠道。

套餐由所属品牌自己创建和发布。渠道不能做这些操作，平台也不替 OEM 发布套餐。

状态：

| 状态 | 含义 |
| --- | --- |
| 待审核 | 已创建，还不能购买 |
| 已发布 | 符合条件的用户可以购买 |
| 已拒绝 | 未通过，以后仍可重新发布 |
| 已下架 | 停止新的购买，已经获得的额度保留 |

待审核可以发布或拒绝。已拒绝、已下架可以重新发布。只有已发布可以下架。待审核不能直接下架。

## 4. 用户额度

用户额度分两种，不能并成一笔可退余额：

- 赠送额度：邀请或活动发放。消费时先扣。不可退款。
- 充值额度：用户付钱后获得。赠送额度用完后再扣。

另有套餐额度，按套餐自己的周期和有效期使用。

请求进来之前，先按合理费用检查可用额度并占用，避免同一份余额被同时花掉。请求完成后，按实际用量和当时的价格结算。实际花费可以高于预估，也可以超过 Key 的上限，账户余额可以为负。没有可靠用量时，这笔请求继续待核对，不用预估金额充当消费。

可用额度或 Key 上限不足时，拒绝新的请求。已经放行的请求仍按实际用量记账。之后充值只补账户里的缺口，不清空这把 Key 已经用掉的金额。

用户弃用后留下的小额缺口，由所属品牌承担。不做催收，不设信用额度，也不自动核销。

## 5. API Key

用户用 API Key 调用模型。一把 Key 可以限制：

- 能用哪些模型，或者不限制模型。
- 在一个计算周期里最多花多少钱。周期为不限时、每月、每季、每年。这是花费上限的计算窗口，不是这把 Key 的到期时间。
- 调用频率和同时进行的请求数。

Key 可以另外设置到期时间。到期后不能再发起新请求。修改花费上限不会顺便改掉到期时间。

## 6. 收款

用户付钱给所属品牌。挂在渠道上的用户也付给该渠道所属的平台或 OEM，不付给渠道。

线上付款进入该品牌自己的商户。订单同时记下两件事：用户是从哪个推广关系来的，钱实际进了哪个品牌。退款回到原来的额度池。

线下收款由品牌财务登记。需要记下客户、实收金额、币种和发放的额度。说明和外部参考号可以不填。系统只记账和发放额度，不向银行打款。同一笔操作重复提交只入账一次。

渠道不能配置商户、确认收款、退款或给用户划拨额度。

OEM 向平台购买服务额度，是另一笔交易。OEM 付款并且收到对应额度后，这笔采购就完成。平台记下服务销售和实际收款。OEM 记下采购支出和得到的额度。平台不等待这些额度被 OEM 的用户用完，也不按 OEM 的零售价计算自己的收入。

## 7. 经营口径

平台和 OEM 各算各的收入、成本和利润。

例：OEM 向平台支付 1,000，获得相应服务额度。之后 OEM 的用户被计费 150，其中按平台结算价实际消耗 100。

- 平台：1,000 的服务销售已经完成。150 不是平台收入。
- OEM：消费收入 150，服务成本 100，这笔 API 毛利 50。那 1,000 是采购，不再扣进这 50。

OEM 把终端售价改成 120 时，OEM 毛利变成 20。平台已完成的销售不变。

无现金的额度调整不是销售。实收现金、协议销售金额和发放给用户的额度分开记录，不互相代替，也不推测汇率。

## 8. 推广与佣金

推广关系是：渠道，其下可以有代理商，代理商和个人推广员再发展个人推广员。

佣金只沿邀请关系向上计算两跳，分别是直接和间接。没有上一级，就只计算存在的那一跳。注册时没有使用他人的推广码，则不产生佣金。

佣金按已经确认的 API 消耗计算，不按充值计算。三个比例是总佣金、直接、间接。直接加间接不得超过总佣金。平台和它的渠道用平台的一套比例。OEM 自己设置比例，并适用于该 OEM 和它下面的渠道。

每人注册都有自己的推广码。默认没有分佣资格。没有资格时，邀请只给对方赠送额度，不发佣金。达到品牌配置的条件后获得资格。条件可以按累计消费或单笔充值设置。

佣金进入佣金钱包，不能用来支付 API。佣金先冻结，到期后解冻。打款在线下完成，线上只登记已经打出的款项。系统不发起转账。

## 9. 冲正与退款

不删除原来的账。退回、撤销和更正都补记一笔对应记录，并指向原记录。同一笔操作只能成功一次。

下面这些是不同的事，不能合成一个退款：

- 退回用户支付的现金。
- 冲回某次消费。
- 释放尚未结算的占用。
- 冲回尚未打款的佣金。
- 登记已经打出、事后又收回的佣金。

消费冲正撤回对应收入。已经发生的供应商成本不因此消失。已经打给推广者的佣金不再从钱包里扣回，另行登记待核对金额。收回也在线下完成，可以分次收回，全部收回后结清。系统不自动追讨，也不从以后的佣金里抵扣。

## 10. 员工

平台岗位：管理员、运营、财务、技术、只读审计。

OEM 岗位：管理员、运营、财务、只读审计。范围只限本 OEM 和它的直属渠道。OEM 员工不能管理供应商、全平台账务和其他 OEM。

渠道由渠道管理员管理本渠道的客户、推广、已授权模型和本人收益。

员工可以兼任岗位，权限合并。只有本公司管理员可以分配岗位、停用或恢复员工。不能改自己的权限，不能停用自己，也不能移除最后一个有效管理员。停用后不能登录，已有会话和该员工的 API Key 失效。

只读审计不能因为兼任其他可读权限而获得资金写入权。真正的收款、退款和发放，始终核对该笔账属于哪个品牌。

## 11. 不做的事

- 无限级代理。
- 渠道自带供应商密钥，或自建模型目录。
- 渠道单独定价、单独收款、单独持有额度池。
- 系统自动向银行或支付机构打款、提现、追回。
- 催收、信用额度和自动核销弃用账户的欠款。
- 把 OEM 的终端销售额算进平台收入。
- 让用户指定供应商或路由。
