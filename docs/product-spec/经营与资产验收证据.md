# 经营、身份、销售、激励与异常处理验收证据

记录日期：2026-10-16。对应产品验收标准 A 编号，记录本次负责领域的实现、已经运行的验证和实际边界。此文不代替整栈浏览器、全部 135 项或真实商户验收，也不覆盖其他负责人尚未汇总的证据。

## 验证口径

- **领域通过**：本行列出的真实 PostgreSQL 领域用例已经执行成功；并非仅编译成功。跨模块页面或外部账户若仍待验证，会在本行明确列出。
- **部分验证**：实现和部分断言有证据，仍有本行明确指出的专门检查未完成；不记为整项通过。
- 每项 PostgreSQL 测试使用隔离库内随机 schema，不依赖演示业务数据。组织/商务/激励的单域夹具会注入明确的 readiness/coverage 协议替身，跨领域 remediation 测试使用真实 organization、commerce、cooperation、incentives、ledger；协议替身不能证明生产采购承载能力。
- 最新六域联合命令为 `go test -race -count=1 ./internal/organization ./internal/branding ./internal/commerce ./internal/incentives ./internal/remediation ./internal/usage`，同时提供两个数据库环境变量、真实 MinIO 19000 和独立模型 HTTP 18090。实际结果依次为 **80.713s、4.337s、48.993s、75.938s、145.434s、31.408s，全通过**。这一次运行已包含佣金来源台账与拒付门槛；其后新增稳定币退款与分次退款须看文末专项证据，不能倒填到该次整组结果中。
- Cloudflare 使用真实 API 格式的隔离 HTTP 协议服务；Logo 使用真实私有 S3/MinIO。无真实 Cloudflare 账户和公网域名材料，不声称已完成公网接入或实际证书签发。稳定币测试使用真实 read-only JSON-RPC 客户端与合成 ERC20 链状态，不声称发生真实链上资金转账。

追加 `remediation/0007_refund_route_versions.sql`。`RecordManualRefundFailure` 独立记录银行/执行方已核实失败或取消的终态、外部凭据和不会再付款的证明；仅记录超时或结果未知不能重开付款。`CloseRefundExecution` 要求原执行已终止，原支付观察必须全部匹配，并通过 payments 的 immutable seal 阻止旧指令再次网络执行。剩余资金 hold 和原 receipt 可退容量不释放，目的地须由客户重新提案、财务重新核实，形成新的不可变版本；授权金额只等于剩余债务。旧路由、旧授权和旧真实付款均保留，迟到实际付款仍可入账，超付只记经营损失，不再扣客户本金。
